## Root cause and change

The agent shared a 105-second deadline between tool selection, tool execution and final synthesis. Real Gemini model calls can each take tens of seconds, leaving the final response starved after genuine tools completed.

Initially Gemini 3.6 Flash and all connections were retained while the timing boundary was repaired. After repeated live 3.6 availability failures, the owner authorized another Gemini Flash model; the successful explicit 3.5 Flash-Lite selection above supersedes that earlier model choice. No new dependencies, provider, credentials, schema or client permissions were introduced.

- Agent turn budget is bounded to 135 seconds, retaining room below the hosted free-plan 150-second runtime for result persistence. Each model request still has a 90-second cap and the remaining whole-turn cap.
- After actual tool results, Gemini 3.6 Flash uses supported minimal thinking for synthesis. Ordinary user reasoning/tool selection stays low; other models retain their existing supported configuration.
- The final minute is reserved for a text answer rather than more tool rounds. Earlier chained discovery/reads and confirmation workflows remain available.
- Function-call signatures and real result/error payloads stay in model history. The prompt asks for a natural answer, including empty results and provider failures, without repeating completed reads.
- Content-free phase timings and phase-specific timeout diagnostics make routing and post-tool failures distinguishable. No provider payloads or credentials are logged.
